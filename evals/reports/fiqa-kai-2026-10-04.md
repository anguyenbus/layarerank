# Decision-2.0-Kai-0.6B as a reranker on FiQA — 2026-10-04

Companion to [fiqa-2026-09-28.md](fiqa-2026-09-28.md) (Laya) and
[fiqa-decider-2026-10-03.md](fiqa-decider-2026-10-03.md) (Strands Decider). Same pools, same
metrics, same gate.

## Summary

- **Off the shelf, Kai passes the gate.** With no training it scores nDCG@10 **0.522** on the test
  split, +0.130 over BM25 (95% CI [+0.100, +0.161]). Untrained Laya (0.422) and untrained Decider 2B
  (0.400) did not get there. It is still below bge-reranker-v2-m3 (0.578) by 0.056 [0.035, 0.077].
- **Fine-tuned, Kai beats bge and ties Decider.** After the same recipe used for Laya and Decider it
  scores **0.618**: +0.041 over bge [+0.023, +0.057], +0.039 over fully fine-tuned Laya
  [+0.024, +0.054], and −0.009 against fine-tuned Decider 2B [−0.024, +0.007], which is a tie.
- **Kai is the cheaper of the two.** 0.6B parameters against 2B, and 64 ms per pair against 157 ms on
  the same RTX 3060. It is still about 5× slower per pair than bge's earlier timing (12.6 ms).
- **Recommendation:** where fine-tuning data exists, prefer fine-tuned Kai over fine-tuned Decider
  (same quality within noise, 2.4× faster). Without fine-tuning, bge remains the better reranker.

## Setup

| | |
|---|---|
| Data | BEIR FiQA; BM25 top-30 pools; 385 test, 281 dev, 3,085 train answerable queries |
| Metrics | nDCG@10 (primary), MRR@10, Recall@10; paired bootstrap, 5,000 resamples |
| Gate | beats BM25 on nDCG@10 with the 95% CI above 0 |
| Model | `vllm-sr/Decision-2.0-Kai-0.6B` at commit `cd49ea38`; Qwen3-0.6B-Base fully fine-tuned by its authors, plus a 1.05M-parameter candidate head; 8,192-token window |
| Hardware | one RTX 3060 12 GB |

Kai is used pointwise: the state is `{"query", "passage"}`, one question is asked per pair, and the
passages are ranked by the answer. The model ships its runtime as code in the repository; the adapter
([evals/kai.py](../kai.py)) imports the packaged model class from the pinned commit and batches across
passages, which the packaged runtime does not do. Scores match the official
`AutoModel(...).system_one` exactly at batch size 1 and within 0.007 when batched (120 FiQA pairs).

## Fine-tuning

Same recipe as Laya and Decider: all positives plus 7 resampled BM25 hard negatives per query, a
listwise softmax over the true-minus-false margins plus 0.5 × BCE, 8 queries per step, AdamW with 5%
warm-up and cosine decay, gradient clipping at 1.0, training rows capped at 512 tokens, best
checkpoint kept by dev nDCG@10 on a 100-query sample.

Differences from the Decider run:

- **What trains:** Kai has no adapter, so the whole backbone except the token embeddings is trained
  along with the head (441.5M of 597M parameters). Freezing the embeddings keeps AdamW within 12 GB;
  peak memory was 9.6 GB.
- **Learning rates:** 2e-5 for the backbone, 1e-4 for the head (Decider: 1e-4 for both).
- **Preset:** `noul-criteria`, the best yes/no preset on dev (Decider: `noul-question`).
- **Length:** 2 epochs, 772 steps, evaluated 4 times per epoch (Decider: 1 epoch).

0.6622). Training took about 13 s per step, 3.2 hours in total including evaluations.

## Caveats

- One dataset, one seed, in-domain fine-tune. Nothing here says how fine-tuned Kai transfers.
- The fine-tune differs from Decider's in preset, epochs and learning rate, so the Kai-vs-Decider tie
  is a comparison of the two results, not a controlled comparison of the two models.
- The untrained `score` preset was not fine-tuned; the recipe needs a yes/no margin.
- bge and Laya were not re-timed in this session.
- The behaviour analysis done for Laya and Decider (AUC, query groups, BM25 and bge blends, cascades)
  has not been repeated for Kai.
- The checkpoint `evals/models/kai-ft-fiqa/` (2.3 GB) is git-ignored and sits on container storage
  that does not survive a recycle or destroy.

## Reproduce

```bash
RUN="uv run --extra gpu --extra eval --extra server python"

# off the shelf: dev sweep, then test
for p in noul-question noul-bare noul-criteria score; do
  $RUN -m evals.run --dataset fiqa --k 30 --split validation --system kai:0.6b:$p
done
$RUN -m evals.run --dataset fiqa --k 30 --system kai:0.6b:score
$RUN -m evals.run --dataset fiqa --k 30 --system kai:0.6b:noul-criteria

# fine-tune, then score the checkpoint
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True $RUN -m evals.finetune_decider --family kai \
  --preset noul-criteria --out kai-ft-fiqa --lr-backbone 2e-5 --epochs 2 --evals-per-epoch 4 \
  --dev-queries 100 --patience 3
$RUN -m evals.run --dataset fiqa --k 30 --split validation --system kai:kai-ft-fiqa:noul-criteria
$RUN -m evals.run --dataset fiqa --k 30 --system kai:kai-ft-fiqa:noul-criteria

# table and gate
$RUN -m evals.report --dataset fiqa --k 30 --candidate kai:kai-ft-fiqa:noul-criteria
```
